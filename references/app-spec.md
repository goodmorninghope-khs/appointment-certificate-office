# 위촉·임명장 발급소 — 화면·데이터 구조

2026-10-29 라이브 화면과 소스(`assets/index.html`)를 읽고 정리했다.

## 화면 (탭 4개)

| 탭 | 하는 일 | 누가 |
|---|---|---|
| 발급하기 | 1 기안 → 2 검토·결재 → 3 발급(번호·코드) → 대상자 전달 | 편집 권한 있는 담당자 |
| 발급대장 | 발급번호·종류·성명·직책·임기·발급일·결재·상태·수령, 검색, 전달/PNG/발급 취소 | 담당자 |
| 내 위촉장 받기 (`#receive`) | 발급번호+수령코드로 본인 문서 열람·PNG 저장, 수령 기록 | 대상자 |
| 진위확인 | 발급번호+진위확인코드로 발급 기록 대조(성명 마스킹, 취소 표시) | 누구나 |

편집 권한이 없는 사람이 열면 대상자 모드(`recipientMode()`)로 바뀐다.

## 기안 입력 칸

- 문서 종류: 위촉장 / 임명장
- 받는 사람: 성명*, 생년월일, 소속, 직위
- 위촉·임명 내용: 직책*, 임기 시작·종료(기본 다음 달 1일부터 2년), 근거 규정, 본문(자동 작성 체크 시 조사 자동 처리), 발급일*
- 발급 기관: 기관명*, 기관장 직함*, 기관장 성명*, 직인 문구(비우면 기관명+직함+인), 직인 이미지 업로드, 기본값 저장
- 검토 체크 3개와 결재권자 성명*

## 문서 이미지

- 캔버스 렌더링, A4 비율 1240×1754px PNG
- 지문(guilloche) 무늬·테두리, 명조체 계열 글꼴, 자동 생성 직인(문구 해시로 모양 결정) 또는 업로드 직인
- 발급 전 미리보기에는 '발급 전' 표시, 발급본에는 발급번호와 진위확인코드

## 번호와 코드

- 발급번호: `연도-일련번호 3자리` (예: 2026-001). 대장 최댓값+1, 충돌 시 최대 8번 다음 번호 시도
- 진위확인코드: `발급번호|종류|성명|생년월일|소속|직위|직책|시작|종료|발급일|기관|직함|기관장|본문`의 SHA-256 앞 8자리 → `XXXX-XXXX`
- 수령코드: 무작위 8자(혼동 문자 제외 32자 알파벳) → `XXXX-XXXX`

## 저장 (Claude 아티팩트 공유 db)

| 컬렉션 | 내용 | 읽는 사람 |
|---|---|---|
| certs/{발급번호} | 발급 기록 전체(개인정보 포함), 상태, 발급자 | 담당자 |
| acks/{발급번호} | 대상자 수령 기록 | 담당자 |
| settings/org | 기관 기본값(직인 이미지 포함 가능) | 담당자 |
| pub/{해시} | 수령용 사본(수령코드로 AES-GCM 암호화), 진위확인용 사본(진위코드로 암호화, 성명 마스킹) | 누구나(문서 id는 번호+코드 해시) |

- 키 유도: PBKDF2(SHA-256, 150,000회, salt = `cert|발급번호`)
- db가 없으면 이 화면 메모리에만 저장(새로고침 시 사라짐), 기관 기본값은 localStorage `rea-cert-org`
- 외부 의존: qrcode-generator 1.4.4 (cdnjs)

## 상태

- 발급 → 유효 / 발급 취소 → 취소 (certs와 pub 진위·수령 사본 모두 '취소'로 갱신)
- 해촉·임기 만료·정정 재발급 상태는 아직 없음
